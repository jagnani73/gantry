# Gantry — Project Guide

Hackathon project for NTU InnovateX 2026 (Track 1: Payments & Financial Infrastructure). Solo builder (NTU student, Student Group entry). This file is the canonical context for working sessions — read it fully before building.

## What Gantry is

A payer-agnostic payment rail on stablecoins. One on-chain `PaymentIntent`, one settlement contract, two doors:

- **Human door:** printed static QR encodes `…/pay/<handle>` → mobile payer page → payer signs an EIP-3009 `transferWithAuthorization` (gasless — tourist needs zero ETH) → relayer settles.
- **Agent door:** HTTP `402 Payment Required` with x402 v2 `PAYMENT-REQUIRED` header; `accepts[]` offers the standard `exact` scheme (any vanilla x402 client can pay) AND a custom `gantry-pbm` scheme (agent session key EIP-712 sig, executed through an on-chain policy wallet).

Both settle through `GantryCore._settle()`: pull funds → swap to XSGD if needed (min-out guard) → pay merchant → emit `IntentSettled`. Merchant dashboard shows both payer types landing in one live feed. That convergence IS the thesis — never build anything that exists for only one door except the thin encoding layers.

**Pitch line:** "x402 standardized how machines pay. Gantry is the rail that lets one merchant accept payments from machines and humans alike."

**Framing is strictly Singapore-centric:** XSGD settlement, hawker/tourist scenes, PayNow's structural gaps (no foreign payers, no agent payers), PBM framing after MAS Project Orchid.

## Architecture (decided — do not relitigate without user)

**Contracts** (`packages/contracts`, Foundry, Solidity ^0.8.24, OZ only for ERC-20/Ownable). **OpenZeppelin comes from npm** (`package.json`, pinned exact to 5.7.0), not `forge install` — OZ's own docs warn a git install can silently follow the unreleased `master` on update, while a published npm version is immutable. Remappings live in **`remappings.txt`, which silently overrides `foundry.toml`** — put mappings there or they are ignored. `forge-std` stays a submodule (test-only, no npm distribution), so a fresh clone needs `git submodule update --init` — **not** `--recursive`, which would drag in OZ's own test submodules. Switching the OZ path changed no executable code (proven: identical source under both layouts with metadata disabled builds byte-identically) but did change the embedded metadata hash, so a fresh build no longer byte-reproduces the deployed bytecode; the on-chain contracts and their Basescan verification are unaffected:
- `GantryCore.sol` — merchant registry (`registerMerchant(handle, payout, categoryId)` = the 2-min onboarding, plus `setMerchantPayout` rotation gated on the current payout), `PaymentIntent` lifecycle, `settleWithAuthorization()` (QR + x402 `exact`; **EIP-3009 `nonce` must equal `intentId`** — binds signature to intent) and `settleFromPBM()` (Agent-door intents only); shared `_settle` with reentrancy guard, 0.5% protocol fee skim (`feeBps=50`, capped 2%); custom errors; `IntentSettled(intentId, merchantId, payer, tokenIn, amountIn, xsgdOut, feeXsgd, door)` — xsgdOut is gross, merchant receives xsgdOut − feeXsgd. Ownable2Step, renounce disabled.
- `AgentPBMWallet.sol` + factory — `owner` (human) funds it and sets `Policy {dailyCap, perTxCap, expiry, categoryBitmap}`; `agentSigner` is the agent's session key. `authorizeSpend()` (onlyCore) verifies EIP-712 sig + all policy dimensions + daily window. Custom errors `PerTxCapExceeded`, `DailyCapExceeded`, `CategoryNotAllowed(uint16)`, `PolicyExpired` — these exact names surface in the demo; facilitator returns them as x402 `invalidReason`.
- `FixedRateSwap.sol` (owner-set rate, seeded 1.3421) behind the `IGantrySwap` interface — this is what ships. **`GantrySwap.sol` (x·y=k AMM) is SKIPPED by decision (7 Aug 2026)**: do not build, deploy, or wire an AMM unless the user explicitly asks. The seam is the point — production FX means real XSGD liquidity via aggregator/RFQ behind the same interface, not a toy pool. Label the demo rate as owner-set everywhere.
- `MockXSGD.sol` (and `MockUSDC.sol`, now deployed-but-unused — the app moved to real Circle USDC on 7 Aug 2026; **removed from `addresses.ts` and from every deploy script's minting on 8 Aug 2026**, it survives only as the Foundry suite's generic EIP-3009 test double and as the historical address in the table below) — both extend a shared hand-written `EIP3009` base (FiatToken-shaped: typehashes, `authorizationState`, events), 6 decimals, open mint. XSGD carries EIP-3009 deliberately: real XSGD supports x402 natively (StraitsX), and XSGD-direct settlement flows through the same authorization door. XSGD exists on NO testnet — mock is the honest option; label it.
- Primary pay token on Sepolia: Circle's real testnet USDC `0x036CbD53842c5426634e7929541eC2318f3dCF7e` (implements EIP-3009, has faucet). Fork-test against it from the start — EIP-3009 domain/sig quirks are a known risk.

**Backend** (`packages/backend`, Node 22 + Express + viem): merchant API; x402-protected routes via `@x402/express` pointed at our own facilitator; facilitator `/verify` + `/settle` (spec-shaped, `@x402/core` types, hand-rolled `gantry-pbm` handler); relayer (holds the only gas key — payers never send transactions); SSE indexer via `watchContractEvent` over WebSocket RPC. SQLite (better-sqlite3) as cache only — chain is source of truth. Pin `@x402/*` versions day one; vendor a ~50-line PAYMENT-REQUIRED/PAYMENT-SIGNATURE codec as insurance (v1→v2 churn risk; v1 examples online show old `X-PAYMENT` headers — ignore them).

**Web** (`packages/web`, Next.js 15 App Router + Tailwind + shadcn/ui + wagmi v2 + RainbowKit): onboarding single form (`/onboard` — the wizard→form cut was taken in M4), printable QR page (`@media print`), payer page `pay/[handle]`, merchant dashboard (live SSE feed with chime + Human/Agent badges and per-row inline FX — amount in + token → XSGD, with net and fee — policy panel with cap meter + Revoke, summary strip). Payer page: ONE signing path (EIP-3009 typed data), TWO key sources — real wallet-connect (product UX, demo clip) and embedded pre-funded burner key behind an env/query flag (deterministic on-stage mode).

**Agent** (`packages/agent`, Vercel AI SDK `ai` + `@ai-sdk/google`, model `gemini-flash-latest` — Google AI Studio free tier; switched from `@anthropic-ai/sdk`/claude-opus-5 on 7 Aug 2026, zero-budget decision): terminal CLI; tools `list_merchants`, `check_my_policy`, `pay_merchant` (deterministic HTTP + signing inside the tool; the LLM narrates via `streamText` multi-step tool loop). 8s LLM timeout → scripted reasoning fallback, visually identical. Separate tiny script pays via unmodified `@x402/fetch` (standard-interop proof).

**Chain/infra:** Base Sepolia (`eip155:84532`); **`BASE_SEPOLIA_RPC_URL` is a comma-separated fallback chain** tried in order (one URL is a valid single-entry list, so old configs still work), with `https://sepolia.base.org` always appended as last resort. Design notes that bind future work:
- **`getAddress` does NOT validate EIP-55** — it validates shape and re-checksums, silently "fixing" a corrupted paste. `isAddress(a, { strict: true })` is the real check (it accepts all-lowercase, rejects all-uppercase). `setMerchantPayout` is gated on the payout address itself, so a mistyped payout is unrecoverable by anyone — this check is the only thing standing in front of that.
- **The AI SDK emits a `start` part before any network I/O**, from the stream's own `start()` callback. Any liveness/timeout logic MUST ignore `start`/`start-step` or it defuses itself ~5ms in. This silently killed the 8s scripted-fallback contract during the M3→M4 Gemini swap; `SYNTHETIC_PARTS` in `packages/agent/src/index.ts` is the guard, and an `AbortController` releases the stalled socket.
- **The compensation invariant applies to onboarding too:** `registerMerchant` proves ownership on-chain (`ownsHandle`) before reporting failure, and returns `alreadyRegistered` with `txHash: null` — otherwise a register that mined past the 20s receipt cap comes back to its own owner as "that handle is taken".
- **A scoped dashboard hides the policy panel and other merchants' rows**, so it must always announce itself — an empty scoped feed is otherwise indistinguishable from a broken one, and `?handle=ah-hock-chicken-rice` renders a header identical to the unscoped view.
- The 30s register cooldown is in-process and **survives `demo:reset`** — space onboarding takes or restart the backend.
- Deferred by triage: no automated coverage for `registerMerchant` itself (chain-touching, matching the repo's existing convention — the pure parts are covered in shared); `lastRegister`/`registerInFlight` are unbounded maps; venue NAT collapses all visitors to one cooldown key.

## Deployment (config committed 8 Aug 2026, never yet run against a host)

Split is forced by SSE: the dashboard feed is a long-lived stream, so the backend cannot be serverless. `vercel.json` at the repo root builds `packages/web` (deploy from the ROOT, leave Vercel's Root Directory unset); `packages/backend/Dockerfile` targets Railway or Fly and **must be built with the repo root as context** (`docker build -f packages/backend/Dockerfile .`) because it installs the pnpm workspace. It deliberately does not use `--prod`: the backend runs TS through `tsx` (a devDependency) and `@gantry/shared` exports `src/index.ts` rather than a build artifact. `.github/workflows/ci.yml` runs lint, typecheck, both node suites and `forge test`; `pnpm install` must precede forge because OZ comes from npm. On a public host set `POLICY_ADMIN_ENABLED=0` and `CORS_ORIGIN` to the Vercel origin. **The payer faucet gates itself** on `NODE_ENV=production` (which the Dockerfile sets) — it transfers real USDC from the only gas key with a per-address cooldown, so a public instance would drain from fresh addresses; the flip side is that burner mode cannot fund on a production host, and a rehearsal started with `NODE_ENV=production` fails at the funding step (the `FaucetDisabled` error and the boot line both say so). **None of this has been executed** — the Dockerfile has never been built, so budget time for a first-build failure.

## Conventions

- pnpm workspaces monorepo. TypeScript everywhere outside `packages/contracts`.
- Everything on `main`, incremental focused commits, Conventional Commits (`feat(contracts): …`). No AI co-author trailers.
- Verify with `pnpm lint` + `tsc --noEmit` (and `forge test` for contracts), not full builds.
- **Milestone review gate:** before declaring any milestone (M0–M4) done, run the PR review skill (`pr-review-toolkit:review-pr`) over the milestone's full commit range (e.g. `git diff <last-milestone-tag-or-commit>..HEAD`), triage findings with the user, and fix agreed ones before sign-off. Same applies to any large multi-commit change outside milestones.
- **The repo is PRIVATE** (checked 8 Aug 2026) despite the original "public from day 1" plan. The submission package lists a *public* GitHub repo as one of its five artifacts, so this must flip before submitting or screeners get a 404 — and the Gemini key (which transited a chat) must be rotated BEFORE it flips, not after. Commit history is feasibility evidence for screeners; keep `.env.example` current.
- Demo-script-driven development: if it doesn't appear in the demo script or submission materials, don't build it.
